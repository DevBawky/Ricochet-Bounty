작업을 시작하기 전에 현재 프로젝트의 다음 구조를 먼저 확인해주세요.

- DamageManager의 Chips, Multiplier, Total Damage 계산 구조
- BallEffect가 Chips와 Multiplier를 증가시키는 모든 위치
- 탄환과 오브젝트의 실제 충돌 위치를 전달할 수 있는 구조
- 모든 탄환이 파괴된 뒤 최종 대미지를 계산하는 구조
- Player Panel의 Text | Adder
- Player Panel의 Text | Multiplier
- Text | Total Damage
- 적 UI의 Enemy_HP_Value
- EnemyDataHolder, RoundManager 또는 현재 적 체력 관리 구조
- 적 처치 후 Result, Clear, GameOver로 이동하는 구조
- 적이 살아 있을 때 다음 발사를 준비하는 구조
- Battle 시작과 종료 및 다른 State 전환 시 UI를 정리하는 구조
- 현재 Canvas의 Render Mode, Canvas Scaler, UI Camera와 월드/UI 좌표 변환 방식

기존 프로젝트의 코드 스타일, 폴더 구조, 네이밍 규칙을 유지해주세요.
기존 DamageManager, Enemy 체력 시스템, 점수와 대미지 계산 공식을 새로 작성하지 말고 현재 구조를 확장해주세요.
작업 전에 Git 작업 트리를 확인하고 사용자가 이미 수정한 관련 없는 파일이나 코드를 되돌리지 마세요.


1. 공통 UI 이동 이미지

Chips, Multiplier, 최종 대미지 전달에 공통으로 사용할 UI Image 기반 이동 연출 구조를 구현해주세요.

필요한 UI Image Prefab과 씬 오브젝트는 SerializeField로 Inspector에서 연결할 수 있게 해주세요.
런타임 중 새로운 Canvas, Manager, 설정 데이터, 루트 UI 또는 대체 Prefab을 자동 생성하지 마세요.
미리 연결된 UI Image Prefab을 기존 Canvas의 지정된 Travel Root 아래에 Instantiate하는 방식은 허용합니다.

각 이동 이미지는 다음 정보를 가져야 합니다.

- 시작 위치
- 목적지 위치
- 전달할 수치
- 이동 시간
- 파동 크기
- 파동 빈도
- 파동 시작 위상
- 파동 방향
- 이미지 색상
- 도착 콜백

이미지가 목적지에 도착하면 콜백을 정확히 한 번만 실행하고 자신을 비활성화하거나 제거해주세요.
빠른 화면 전환, Battle 종료, GameOver, Clear 또는 다른 State 전환 시 남은 이동 이미지를 안전하게 정리할 수 있게 해주세요.
강제 정리된 이미지는 도착 콜백을 실행하지 않아야 합니다.


2. 이동 시간 설정

다음 기본 이동 시간을 Inspector에서 설정할 수 있게 해주세요.

- Chips Image Travel Duration
- Multiplier Image Travel Duration
- Damage Image Travel Duration

각 이미지의 실제 이동 시간은 다음 공식으로 이미지마다 한 번 계산해주세요.

actualDuration = baseDuration × Random.Range(0.8f, 1.2f)

기본 시간이 0 이하로 입력되면 0.01초 이상의 안전한 값으로 보정해주세요.
이동 속도를 직접 무작위로 정하지 말고 목적지에 도착하는 전체 시간을 기준으로 이동을 제어해주세요.
Time.deltaTime 또는 Time.unscaledDeltaTime을 사용하여 프레임 속도와 관계없이 계산된 시간 안에 도착하게 해주세요.


3. Sin 파동 이동

이미지는 시작점과 목적지 사이를 보간하면서 Sin 파동 경로로 이동해야 합니다.

- 기본 위치는 Vector2.Lerp 또는 동등한 방식으로 계산
- 시작점에서 목적지로 향하는 경로 벡터 계산
- 경로에 수직인 정규화 벡터 계산
- Sin 값을 수직 벡터 방향으로 더해 파동 경로 생성
- 목적지에 가까워질수록 파동 크기를 줄여 마지막 위치가 목적지와 정확히 일치

다음 값은 Inspector에서 범위를 조정하고 이미지마다 무작위로 결정할 수 있게 해주세요.

- Minimum Wave Amplitude
- Maximum Wave Amplitude
- Minimum Wave Frequency
- Maximum Wave Frequency
- Random Start Phase 사용 여부
- Random Wave Direction 사용 여부

파동 방향은 양수 또는 음수 방향을 무작위로 선택할 수 있어야 합니다.

5. Chips 획득 처리

기존 ScoreObject, BallEffect 또는 점수 증가 코드에서 Chips를 즉시 DamageManager에 적용하는 모든 위치를 확인하고 다음 흐름으로 변경해주세요.

1. 충돌한 실제 월드 위치를 얻는다.
2. 월드 위치를 현재 Canvas의 로컬 좌표로 변환한다.
3. 해당 위치에 Chips UI 이동 이미지를 생성한다.
4. 목적지는 Text | Adder의 RectTransform을 사용한다.
5. 이미지에 실제로 전달할 Chips 값을 저장한다.
6. 이미지가 목적지에 도착했을 때만 DamageManager의 Chips 목표값을 증가시킨다.
7. Text | Adder 표시값은 현재 표시값에서 최신 목표값까지 부드럽게 증가시킨다.

이미지 생성 시점에는 실제 Chips 값을 증가시키지 마세요.
점수 배율 증가 업그레이드가 있다면 기존 적용 규칙을 유지하되 한 번만 적용해주세요.
같은 Chips가 생성 시점과 도착 시점에 중복 적용되지 않게 해주세요.
정확한 충돌 위치를 얻을 수 없는 효과는 해당 탄환의 현재 위치 또는 기존 흐름에서 얻을 수 있는 안전한 월드 위치를 사용해주세요.


6. Multiplier 획득 처리

Multiplier도 Chips와 동일한 방식으로 처리해주세요.

1. 충돌 위치에 Multiplier UI 이동 이미지 생성
2. 목적지는 Text | Multiplier의 RectTransform 사용
3. 이미지에 전달할 Multiplier 값 저장
4. 이미지 도착 시에만 실제 Multiplier 목표값 증가
5. Text | Multiplier 표시값을 최신 목표값까지 부드럽게 보간

이미지 생성 시점에는 실제 Multiplier를 증가시키지 마세요.
Multiplier가 float이면 기존 프로젝트의 소수점 표시 형식을 유지해주세요.


7. Chips와 Multiplier 텍스트 Lerp

DamageManager가 관리하는 실제 목표값과 UI가 표시하는 현재 값을 분리해주세요.

필요한 표시 상태 예시:

- displayedChips
- targetChips
- displayedMultiplier
- targetMultiplier

Chips 또는 Multiplier 이미지가 도착하면 target 값만 증가시키고, UI는 displayed 값에서 최신 target 값까지 이동해야 합니다.

다음 값을 Inspector에서 설정할 수 있게 해주세요.

- Score Text Lerp Duration 또는 Score Text Lerp Speed

여러 이미지가 연속 도착해도 보간 코루틴을 매번 처음부터 강제로 재시작하지 마세요.
현재 표시값에서 계속 바뀌는 최신 목표값을 자연스럽게 추적해야 합니다.
Chips는 정수 형식, Multiplier는 기존 소수점 형식을 유지해주세요.
보간 완료 시 표시값을 목표값과 정확히 일치시켜 부동소수점 오차가 남지 않게 해주세요.


8. 점수 연출 완료 확인

현재 이동 중인 Chips 이미지 수와 Multiplier 이미지 수를 카운터로 각각 관리해주세요.

- 이미지 생성 시 해당 카운터 증가
- 정상 도착 또는 강제 정리 시 정확히 한 번 감소
- 매 프레임 전체 UI 오브젝트를 Find하거나 검색하지 않음

다음 조건이 모두 충족된 뒤에만 최종 대미지 계산을 시작해주세요.

- 활성 탄환 수가 0
- 이동 중인 Chips 이미지 수가 0
- 이동 중인 Multiplier 이미지 수가 0
- Chips 표시 Lerp 완료
- Multiplier 표시 Lerp 완료

최종 대미지 계산과 턴 결과 처리가 중복 실행되지 않도록 플래그 또는 기존 상태/코루틴 방어 구조를 사용해주세요.


9. 최종 대미지 계산

기존 DamageManager의 공식대로 최종 대미지를 정확히 한 번만 계산해주세요.
Chips와 Multiplier 공식 또는 반올림 규칙을 변경하지 마세요.
최종 대미지 이동 이미지마다 최종 대미지를 다시 계산하지 마세요.


10. 최종 대미지 숫자 카운트업 연출

최종 대미지 계산이 끝나면 Text | Total Damage의 표시값을 즉시 최종값으로 바꾸지 말고 0부터 최종 대미지까지 차근차근 증가시키세요.

다음 값을 Inspector에서 설정할 수 있게 해주세요.

- Final Damage Count Up Duration
- 기본값: 0.5초

요구사항:

- 시작 표시값은 정확히 0
- 종료 표시값은 계산된 finalDamage와 정확히 일치
- 설정된 전체 시간 n초를 기준으로 보간
- 프레임 속도와 관계없이 동작
- 정수 텍스트 형식 유지
- Battle 종료나 State 전환 시 안전하게 중단 및 초기화
- 최종 대미지가 0인 경우에도 완료 상태가 즉시 올바르게 처리

최종 대미지 이미지 생성은 이 카운트업이 완전히 끝나기 전에는 시작하지 마세요.


11. 최종 대미지 표시 후 대기

최종 대미지 숫자가 최종값에 정확히 도달한 뒤 일정 시간 대기한 다음 대미지 이미지를 생성해주세요.

다음 값을 Inspector에서 설정할 수 있게 해주세요.

- Final Damage Particle Delay
- 기본값: 1초

대기 시간 m초가 지나기 전에는 대미지 이미지를 생성하거나 적 HP를 감소시키지 마세요.
빠른 State 전환으로 대기가 취소되면 이후 이미지 생성과 대미지 콜백도 실행되지 않아야 합니다.


12. 최종 대미지 이미지 개수와 정수 분배

기본적으로 최종 대미지 30마다 대미지 이미지 하나를 생성해주세요.

imageCount = CeilToInt(finalDamage / 30f)

- Damage Per Image 기본값: 30
- Maximum Damage Image Count 기본값: 100
- imageCount는 1부터 100 사이로 제한
- finalDamage가 3000을 초과해도 최대 100개 유지
- 이미지 개수가 제한되면 이미지 하나가 담당하는 대미지를 자동으로 증가
- 나머지 정수 대미지는 앞쪽 일부 이미지 또는 마지막 이미지에 분배
- 모든 이미지가 가진 대미지 합은 반드시 finalDamage와 일치

예시:

finalDamage = 6000
imageCount = 100
각 이미지는 기본적으로 60 Damage 담당

finalDamage가 나누어떨어지지 않아도 대미지를 버리거나 float 오차를 만들지 마세요.


13. 대미지 이미지 순차 생성과 최종 대미지 카운트다운

Final Damage Particle Delay가 끝나면 모든 대미지 이미지를 같은 프레임에 한꺼번에 생성하지 말고 순차적으로 생성해주세요.

다음 값을 Inspector에서 설정할 수 있게 해주세요.

- Damage Image Spawn Interval
- 권장 기본값: 0.03초

각 대미지 이미지가 생성될 때 다음 흐름을 실행해주세요.

1. Text | Total Damage 위치에 해당 대미지 이미지 생성
2. 이미지에 자신이 담당할 정수 대미지 저장
3. Text | Total Damage의 목표 표시값에서 해당 이미지 담당 대미지만큼 차감
4. 현재 표시값에서 계속 바뀌는 최신 목표값까지 자연스럽게 감소
5. 다음 이미지도 설정된 간격 후 생성

최종 대미지 숫자 감소는 이미지의 생성과 연결되어야 하며 적 HP 적용 시점과는 분리해주세요.
이미지가 생성됐다고 적 HP를 즉시 감소시키지 마세요.
마지막 대미지 이미지가 생성되면 Text | Total Damage의 목표값은 정확히 0이어야 합니다.
모든 이미지 생성이 끝난 뒤 표시값도 정확히 0에 도달해야 하며 음수가 되면 안 됩니다.

여러 이미지가 생성될 때 최종 대미지 감소 보간을 매번 처음부터 재시작해 끊겨 보이게 하지 마세요.
현재 표시값이 계속 변경되는 최신 목표값을 추적하게 해주세요.


14. 최종 대미지 이미지 이동

대미지 이미지는 Text | Total Damage의 RectTransform 중심에서 시작해주세요.
목적지는 Enemy_HP_Value의 RectTransform 또는 해당 Image 중심을 사용해주세요.

각 이미지의 실제 이동 시간:

actualDuration = Damage Image Travel Duration × Random.Range(0.8f, 1.2f)

파동 크기, 빈도, 시작 위상, 방향도 설정 범위에서 이미지마다 무작위로 결정해주세요.
대미지 이미지가 목적지에 도착하면 자신이 저장한 대미지만 적의 목표 체력에 적용해주세요.
이미지가 이동하는 동안 적 체력을 미리 감소시키지 마세요.


15. Enemy HP Lerp

적의 실제 목표 체력과 UI에 표시되는 체력값을 분리해주세요.

대미지 이미지가 도착할 때마다 다음 흐름을 실행해주세요.

1. 이미지가 가진 대미지만큼 적의 목표 체력 감소
2. 목표 체력은 0보다 작아지지 않게 보정
3. Enemy HP 텍스트가 있다면 목표 체력 기준으로 갱신
4. Enemy_HP_Value.fillAmount는 현재 표시값에서 최신 목표값까지 Lerp

다음 값을 Inspector에서 설정할 수 있게 해주세요.

- Enemy HP Lerp Duration 또는 Enemy HP Lerp Speed

여러 이미지가 연속 도착해도 HP Lerp를 매번 처음부터 강제로 재시작하지 마세요.
현재 표시 중인 HP에서 계속 변경되는 최신 목표 HP를 자연스럽게 추적해야 합니다.
fillAmount는 0부터 1 사이로 제한해주세요.
모든 연출 완료 시 표시 체력과 실제 체력이 정확히 일치해야 합니다.


16. 최종 대미지 연출 완료 조건

다음 상태를 카운터 또는 명확한 플래그로 관리해주세요.

- 아직 생성되지 않은 대미지 이미지가 있는지
- 생성되어 이동 중인 대미지 이미지 수
- 모든 이미지에 분배된 대미지 합
- 실제 적 목표 HP에 적용 완료된 대미지 합
- Text | Total Damage의 0까지 감소 완료 여부
- Enemy HP Lerp 완료 여부

다음 조건이 모두 충족되어야 최종 대미지 연출 완료로 판단해주세요.

- 모든 대미지 이미지 생성 완료
- 모든 대미지 이미지 목적지 도착
- 적용된 대미지 합이 계산된 finalDamage와 일치
- Text | Total Damage 표시값이 정확히 0
- Enemy HP Lerp 완료


17. 전투 결과 처리 시점

대미지 이미지가 생성 또는 이동 중이거나, 최종 대미지 텍스트와 HP가 보간 중일 때 적 처치 및 Result 이동을 실행하지 마세요.

모든 최종 대미지 연출 완료 후에만 적 처치 여부를 판단해주세요.

- 적 체력이 0 이하라면 기존 적 처치 보상과 Result/Clear 흐름 실행
- 적이 살아 있다면 기존 다음 발사 준비 흐름 실행
- 플레이어 라이프 감소와 GameOver 판단도 최종 연출 이후 실행
- 기존 보상, OnDeath, Result, Clear, GameOver가 중복 실행되지 않도록 방어


18. 좌표 변환

현재 Canvas Render Mode를 확인하고 다음 모드에 맞는 좌표 변환을 사용해주세요.

- Screen Space Overlay
- Screen Space Camera
- World Space

월드 충돌 위치를 UI RectTransform 위치로 바꿀 때 다음 참조를 사용해주세요.

- 월드 위치를 촬영하는 실제 World Camera
- Canvas.worldCamera 또는 Overlay일 때 null인 UI Camera
- 현재 Canvas 또는 지정된 Travel Root RectTransform
- RectTransformUtility.WorldToScreenPoint
- RectTransformUtility.ScreenPointToLocalPointInRectangle

Travel Root의 Pivot과 이동 이미지의 Anchor 차이까지 고려하여 anchoredPosition이 해상도나 Canvas Scaler 설정에 따라 어긋나지 않게 해주세요.


19. Battle 초기화와 정리

새 Battle 또는 새 Turn 시작 시 다음 상태를 초기화해주세요.

- 이동 중인 Chips 이미지
- 이동 중인 Multiplier 이미지
- 아직 생성되지 않은 Damage 이미지
- 이동 중인 Damage 이미지
- 각 이미지 카운터
- 진행 중인 점수 텍스트 Lerp
- 진행 중인 최종 대미지 카운트업
- 진행 중인 최종 대미지 대기
- 진행 중인 최종 대미지 카운트다운
- 진행 중인 Enemy HP Lerp
- 최종 대미지 계산/적용/완료 플래그
- Text | Total Damage 표시값

Battle 종료, Result, GameOver, Clear, MainMenu 또는 다른 State 이동 시에도 남아 있는 이미지와 대기/보간을 안전하게 정리해주세요.
이전 Battle 또는 Turn의 이미지 도착 콜백이 다음 Battle의 점수나 HP를 변경하지 않도록 generation ID, cancellation token 또는 동등한 방어를 사용해주세요.


20. 구현 원칙

- 기존 DamageManager와 Enemy 체력 시스템을 최대한 재사용
- 점수와 최종 대미지 계산 공식 및 기존 반올림 규칙 유지
- 실제 수치 적용 시점만 UI 이동 연출과 연결
- 매 프레임 Find, FindObjectOfType 또는 전체 오브젝트 검색 금지
- UI 참조는 SerializeField로 Inspector 연결
- 런타임 중 새 Canvas, Manager, 설정 데이터, 루트 UI 자동 생성 금지
- 이벤트 리스너 중복 등록 방지
- 이미지 도착 콜백 정확히 한 번 실행
- 빠른 버튼 입력과 State 전환에서 수치 중복 적용 방지
- 필수 참조가 없으면 NullReference 대신 명확한 경고와 안전한 기존 게임플레이 fallback 제공
- finalDamage가 0인 경우에도 무한 대기하지 않음
- TimeScale 영향을 받지 않아야 하는 UI 연출은 unscaled time 사용 고려
- 사용자 기존 변경사항과 관련 없는 파일 보존
